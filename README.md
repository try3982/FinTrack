## 디자인 패턴 학습을 위한  계좌 관리 프로젝트

사용자가 예금·적금·대출 계좌를 개설하고 입출금·이체·대출·해지·복구를 할수 있는     
계좌관리 프로젝트

# 계좌 관리 프로젝트 요구사항

## 1. 계좌 생성 및 관리

### 1.1 계좌 개설

-  요구사항
    - [x] 사용자는 새로운 계좌를 개설할 수 있어야 한다.
    - [x] 계좌 유형(예금, 적금, 대출 등)을 선택할 수 있어야 한다.
    - [x] 개설 시 초기 예치금이 설정될 수 있어야 한다.(예금: 1000원, 적금 :10000원, 대출: 0원 허용)
    - [x] 각 계좌는 고유한 계좌 번호를 가져야 한다.
-  예외 처리
    - [x] 동일한 계좌 번호가 이미 존재하면 생성 불가
    - [x] 최소 예치금 미만일 경우 계좌 개설 불가

### 1.2 계좌 해지

-  요구사항
    - [x] 사용자는 필요에 따라 계좌를 해지할 수 있어야 한다.
    - [x] 계좌 해지 시 남은 잔액은 등록된 출금 계좌로 송금되어야 한다.
    - [x] 해지된 계좌는 더 이상 사용 불가 상태여야 한다.
    - [x] 일정 기간(예: 3개월) 동안 계좌 복구가 가능해야 한다.
-  예외 처리
    - [x] 계좌에 미결제 대출이나 자동이체 등록이 있으면 해지 불가
    - [x] 출금 계좌가 없거나 잘못되었을 경우 해지 실패
    - [x] 계좌 해지 후 일정 기간 동안 신규 계좌 개설 제한 가능

### 1.3 계좌 정보 조회

-  요구사항
    - [x] 사용자는 본인의 계좌 목록을 조회할 수 있어야 한다.
    - [x] 특정 계좌의 상세 정보(잔액, 개설일, 계좌 상태)를 확인할 수 있어야 한다.
    - [x] 특정 계좌의 거래 내역(최근 1개월 기본 제공)을 조회할 수 있어야 한다.
-  예외 처리
    - [ ] 본인 계좌가 아닌 경우 조회 불가

### 1.4 계좌별 잔액 관리

-  요구사항
    - [x] 계좌 잔액은 입출금이 발생할 때마다 실시간으로 반영되어야 한다.
    - [x] 최소 잔액 제한이 있는 계좌의 경우, 출금 시 최소 잔액을 유지해야 한다.
    - [x] 잔액이 부족할 경우 출금 및 이체가 제한되어야 한다.
- ❗ 예외 처리
    - [x] 출금 가능 잔액보다 높은 금액을 요청할 경우 오류 반환
    - [x] 시스템 장애 시 잔액 업데이트가 보장될 수 있도록 트랜잭션 처리 필요

## 2. 입출금 및 이체 기능

### 2.1 입금 기능

-  요구사항
    - [x] 사용자는 본인의 계좌에 입금할 수 있어야 한다.
    - [x] 입금 시 즉시 잔액이 반영되어야 한다.
    - [x] 현금 입금, 계좌 이체 등의 다양한 입금 방식 지원
-  예외 처리
    - [x] 계좌가 정지되었거나 해지된 경우 입금 불가
    - [x] 최대 입금 한도를 초과할 경우 입금 불가

### 2.2 출금 기능

-  요구사항
    - [x] 사용자는 본인의 계좌에서 출금할 수 있어야 한다.
    - [x] 출금 가능 금액은 현재 잔액에서 출금 수수료를 제외한 금액까지 가능해야 한다.
    - [x] ATM 출금, 타 계좌 이체 등의 출금 방식 지원 한다.

### 2.3 계좌 간 이체 기능

-  요구사항
    - [x] 사용자는 본인의 계좌에서 다른 계좌로 금액을 이체할 수 있어야 한다.

## 3. 거래 내역 조회 및 분석

### 3.1 특정 기간 거래 내역 조회

-  요구사항
    - [x] 사용자는 특정 기간(예: 최근 3개월, 6개월, 1년)의 거래 내역을 조회할 수 있어야 한다.
    - [x] 검색 필터(입출금, 이체 등 거래 유형)를 적용할 수 있어야 한다.
    - [x] 내역은 날짜 기준으로 정렬되어야 한다.

## 4. 대출

#### 4.1. 예금 담보 기반 대출

-  요구사항
    - [x] 고객이 자신의 예금 계좌를 담보로 설정하고 해당 잔액의 일정 비율만큼 대출을 받을 수 있다(회원 등급 有).
    - [x] 계좌 상태가 ACTIVE이며 잔액이 출금 불가 예치금으로 전환(계좌 상태가 LOCKED로 바뀜)
    - [x] 담보는 계좌 잔액의 회원 등급에 따라 다름.

#### 4.2 대출상태

-  요구사항
    - [ ] 대출은 상환 다음과 같은 종류로 한다.
        - 상환: 대출 금액을 값는 행위
        - 연체: 상환 기간을 넘겨 대출금을 갚지 못하는 경우
        - 중도 상환: 대출 만기 전에 대출금을 갚는 행위
    - [ ] 대출금 상환을 2회(2개월) 연속 하지 못하면 담보 계좌에서 자동 출금한다.

#### 관계 정리

##### 1. 사용자(Users) <-> 계좌(Accounts)

- 관계: 한 사용자는 여러개의 계좌를 가질수 있다. (1:N)
- 관계 이름: 사용자는 여러 계좌를 소유한다.
- 계좌는 하나의 사용자에 속한다.

#### 2. 사용자(Users) <-> 수수료(Fee)

- 사용자 1명은 1개의 정책(등급, 수수료 정책)을 가진다. (1:1)
- 관계 이름: 사용자는 거래 한도 및 수수료 정책을 가진다.
- 정책은 특정 사용자 등급에 적용된다.

#### 3. 사용자(Users) <-> 대출(Loans)

- 관계: 한 사용자는 여러 건의 대출을 신청할 수 있다. (1:N)
- 관계 이름: 사용자는 여러 대출을 신청할 수 있다.
- 대출은 하나의 사용자에게 속한다.

##### 4. 계좌(Accounts) <-> 거래내역(Transactions)

- 관계: 계좌 1개에 여러 거래내역이 존재한다. (1:N)
- 관계 이름: 계좌는 여러 거래내역을 가진다.
- 거래는 하나의 계좌에서 발생한다.

#### 5. 거래내역(Transactions) <->  수취 계좌(Accounts)

- 관계: 거래가 이체일 경우 수취 계좌가 존재할 수 있다. (N:1)
- 관계 이름: 이체 거래는 수취 계좌를 참조할 수 있다.
- 수취 계좌는 이체 거래의 대상이 된다.

#### 6. 대출(Loans) <-> 담보 계좌(Accounts)

- 관계: 대출은 1개의 예금 계좌를 담보로 설정할 수 있다. (1:1 또는 N:1)
- 관계 이름: 대출은 담보 계좌를 가진다.
- 담보 계좌는 대출의 보증이 된다.

#### 7. 거래(Transactions) <-> 대출(Loans)

- 사용자 등급 및 조건에 따라 다양한 정책이 적용된다. (1:N or 조건 기반)
- 사용자의 등급과 거래 조건은 대출 정책에 영향을 준다.
- 정책은 특정 사용자 조건에 따라 정의된다.



## Design Pattern

### 계좌 생성 및 관리 관련

#### 적용 기능

- 계좌 개설 시 다양한 계좌 유형(예금, 적금, 대출 등) 객체 생성
- 계좌 해지 및 정보 조회 처리

#### 추천 패턴

1. Factory Pattern
    - 설명: 다양한 종류의 계좌 객체를 생성할 때 생성 로직을 캡슐화하여 재사용성과 확장성을 높인다.
    - 적용 예: AccountFactory 클래스를 통해 계좌 유형에 따라 서로 다른 계좌 객체를 생성

2. Singleton Pattern
    - 설명: 계좌 관리나 트랜잭션 처리에 대해 하나의 인스턴스만 존재하도록 하여 일관된 데이터 관리를 보장한다.
    - 적용 예: AccountManager 또는 TransactionManager를 싱글톤으로 구현

---

### 입출금 및 이체 기능 관련

#### 적용 기능:

- 입금, 출금, 계좌 간 이체 처리
- 출금 수수료, 한도 관리 및 수수료 정책 적용

#### 추천 패턴

1. Strategy Pattern
    - 설명: 거래 수수료, 한도 등 정책을 동적으로 교체할 수 있도록 캡슐화하여 상황에 맞게 전략을 선택한다.
    - 적용 예: FeeStrategy 인터페이스와 이를 구현한 NormalFeeStrategy, PremiumFeeStrategy 등으로 정책 관리

2. Command Pattern
    - 설명: 입금, 출금, 이체 등의 트랜잭션을 캡슐화하여 실행, 취소(Undo) 기능을 구현할 때 유용하다.
    - 적용 예: DepositCommand, WithdrawCommand, TransferCommand 클래스로 각 작업을 객체로 다루어 재실행이나 취소 기능 제공

---

### 거래 내역 조회 및 분석 관련

#### 적용 기능

- 특정 기간 거래 내역 조회
- 거래 유형별 필터링 및 정렬 기능

#### 추천 패턴

1. Decorator Pattern
    - 설명: 기본 거래 내역 조회 기능에 추가적인 필터링, 정렬, 데이터 포맷팅 등의 기능을 동적으로 추가할 수 있다.
    - 적용 예: 거래 내역 객체에 데코레이터를 적용해 여러 단계의 데이터 가공 처리 구현
